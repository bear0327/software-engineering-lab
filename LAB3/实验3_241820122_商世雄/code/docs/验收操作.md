# 建议验收顺序

请先使用演示数据操作，不填真实个人资料。以下日期均选择今天之后、已维护日历的日期。

## 一、游客与顾客

1. 启动程序，点击“游客查房”，查看南京酒店。填入住、离店、间数与人数，点击查询；选择房型查看逐夜价格。
2. 游客点击预订，应提示需要顾客登录。只填一个日期应提示补齐。无日期只能浏览，不显示可订承诺。
3. 返回登录，使用customer登录。查入住为明天、住两晚、1间2人的方案；查看报价明细。
4. 点击预订，填写联系人与电话，接受总价。应返回订单号；重复提交同一选择和联系人只返回原订单，不新扣库存。
5. 打开“我的订单”，查看日期、逐夜成交价、状态和版本。详情电话遮挡中间部分，后台记录仍用于酒店联系。
6. 待确认时修改住宿，缩短为一晚，接受新价格；重新查看订单。待确认修改会重新计算30分钟确认期限。
7. 可再建立一笔订单，测试取消。刷新后状态为已取消，原逐夜明细保留，未消费库存归还。

## 二、酒店人员

1. 退出，用staff登录，默认只见南京泊岸酒店订单。staff2属于另一家酒店，不能访问第一家的订单和日历。
2. “房型资料”查看并新增一个房型；“每日库存与价格”输入房型编号，维护日期区间的供给与单晚价。
3. 选择原待确认订单并确认，版本增加；确认不再次扣房。
4. 回到顾客账号：已确认订单只能改联系人，不能直接改住宿方案。
5. 酒店人员可选择另一笔待确认订单并填写原因拒绝；“通知待办”出现任务，可标记已联系或重试。
6. 入住只允许计划入住当天。订单选择明天时今天办理应被拒绝；不要修改系统时间做测试，使用自动化可控时钟验证边界。
7. 对合法入住订单，现场核验确认后状态变已入住。计划离店日及之后才可正常退房，不恢复历史占用。

## 三、管理员

1. 用admin登录，在“酒店审核与启停”登记酒店。新酒店处于待审核，未批准前不向游客开放。
2. 启停已有酒店须写原因。停业后顾客不能新订；旧订单不删除，待确认和已确认可逐笔异常取消。
3. 已入住不能用异常取消变成取消，需人工协调。取消后通知待办与操作日志保留。
4. 创建绑定唯一酒店的工作人员，测试停用；原账号既有会话和新登录都应失效。
5. 查看全平台统计与日志；酒店人员仅可查看本酒店，顾客仅可查看本人订单历史。
6. 点击数据一致性检查，应显示 `ok: true`；立即备份，核对输出文件名与SHA256清单。

## 四、可复现的边界与并发验证

```powershell
python -m pytest tests/test_lifecycle.py -q
python -m pytest tests/test_security.py -q
python -m pytest tests/test_concurrency.py -q
python -m pytest tests/test_gui.py -q
```

重点包括：29分59秒可确认、30分钟整拒绝且超时状态真正提交；入住日18:00取消边界；未入住只归还未来夜；停售缩短允许/增加拒绝；任一晚失败整体回滚；20个不同顾客竞争最后一间，仅1个成功；20次相同键重试只有一次库存效果；确认取消竞争按合法提交顺序处理。

恢复演练见README，使用新文件，不覆盖已有数据库。自动化脚本均创建隔离数据，不要把测试sqlite文件当作正式业务数据提交。
