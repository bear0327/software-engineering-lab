# 实现和修订事实

本文件是工具与修订的客观记录，供复现和报告核对，不代替实验报告中的个人分析。

## 使用的辅助工具

- OpenCode与GPT-6.1 Sol：根据LAB1需求、LAB2规则组织Python实现、测试及构建脚本。
- Python 3.12、Tkinter、SQLite：实现原生桌面界面、业务与本地持久化。
- Ruff、Pylint：检查格式、导入、常见错误和代码规范。
- pytest、pytest-cov：隔离数据库、可控时钟、并发及真实Tk控件测试；保留原始结果。
- setuptools/build、PyInstaller：构建wheel、源码发行包和Windows便携程序，真实执行冻结程序自检。
- PlantUML 1.2025.10：导出与实现一致的9张UML图。
- Git：本地真实提交，向课程仓库新增LAB3，不覆盖LAB1/LAB2或移动旧标签。

代码与界面没有额外水印。实验要求中的工具使用说明仍应根据真实情况填写，不虚构个人手工编写或操作经历。

## 实际发现和处理的问题

| 问题 | 原因与处理 | 对应验证 |
| --- | --- | --- |
| 超时状态被异常回滚的风险 | 到期转态在业务保存点内完成后返回错误字典，外层先提交再向调用方抛业务错误 | `test_strict_expiry_commits_before_rejection` |
| SQLite没有PostgreSQL的行锁 | 用BEGIN IMMEDIATE包围读检查与所有夜更新，按固定顺序处理净变化 | 最后一间、同键重试、确认/取消竞争测试 |
| Windows自检清理失败 | sqlite3连接的with只管理事务、不自动关闭连接；备份校验改用contextlib.closing | `test_self_test_releases_files_on_windows`、源码/EXE自检 |
| 生命周期测试第二天认证过期 | 测试跨天后仍用8小时会话；按实际规则重新登录，而非延长生产会话 | 正常入住、退房历史库存测试 |
| 第二家酒店日历默认编号错误 | 原默认房型1属于第一家；改为从授权房型列表选择首项，无房型时不查询 | staff2页面构造和日历默认房型3断言 |
| 日志隔离测试把初始化日志算为泄露 | 第二家酒店本来就有初始化审核及日历记录；限定检查第一家新建订单的BOOKING_CREATE动作 | `test_customer_log_scope_and_no_phone_leak` |
| 人员管理缺少审计与改密码入口 | 人员创建启停写入相同事务的审计，增加改密码并撤销全部会话 | 账号停用、改密码、会话撤销测试 |
| GUI业务回调随机新请求键 | 同一页面按内容/版本缓存请求键，基础设施失败后重试保持同键 | GUI重复预订只有一笔订单 |
| 单纯格式检查留下长SQL字面量 | 长SQL拆为相邻字符串，统一4空格缩进、导入排序和100字符行宽 | Ruff、格式检查、Pylint原始日志 |
| 改单只记录旧合计，无法核对旧逐夜价 | 审计快照增加原逐夜日期、单价与数量；不记录联系电话原文 | `test_modification_audit_preserves_old_nightly_prices` |
